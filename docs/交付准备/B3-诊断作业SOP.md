## 一、总览（含人工环节与耗时）

| 步 | 环节 | AI 做什么 | **人做什么（谁）** | 人工耗时 | 产出 |
| --- | --- | --- | --- | --- | --- |
| **E1** | 文档接入与归属 | 自动分类 + 系统归属 + 置信度 | **对接人**按**系统维度批量确认**（非逐份）；置信 <0.6 的逐条确认 | 30-60 分钟 | 文档库 |
| **E2** | 知识抽取 | 结构型 / 表格型 / 句式型抽取 → K1-K6 | **交付人抽检 ≥20%**（**必须含全部低置信项**） | 2-4 小时 | 事实条目 |
| **E3** | 时效校验 | 版本 / 日期一致性检查 | **对接人**确认「文档是否对应当前版本」 | 15 分钟 | 时效标注 |
| **E4** | 落差识别（硬节省） | K2×K3 / K5×K3 / 闲置 → 三类清单 + 金额 | **各系统负责人逐条确认**（含「试点 / 备用 / 合规留存」排除）→ **过检签核** | 1-2 小时 | 硬三类清单 |
| **E5** | 机会匹配 | 匹配机会卡 + 排序（可执行性 / 价值） | **业务部门**做候选机会排序取舍确认（反馈回流）；落地归属走 **D8 三态判定**（✅ 成立并落地 / 🟡 方案需调整 / ❌ 不成立 + 结构化理由） | 30 分钟 | 机会清单 |
| **E6** | 方案与交付 | 报告四模式 + 执行档案与闭环 + Agent Spec | **交付人 + 复核人复核**（见 B5） | 1-2 小时 | 报告 + 执行档案 |

> **接单评估不在 E 链路内**——E 链路为 **E1-E6 六步**；**授权与接单经商务合同约定**（不属系统环节，PRD 术语表 E 项），售前工具见《[B1 文档就绪度评估表](./B1-文档就绪度评估表.md)》。

**典型一次诊断的人工投入：约 1-2 人日**（不含客户侧确认等待时间）。
> ⚠️ **该数字为设计估算，必须在真实项目实测后校准**（12.7 ② 单位经济的输入；当前实测受限于"无真实企业文档"尚未完成）。

## 二、关键纪律（违反即返工）

| # | 纪律 | 为什么 |
| --- | --- | --- |
| 1 | **抽检 ≥20%，且必须含全部低置信项** | 低置信项出错概率最高；只抽高置信 = 自欺（也是 F16 成熟做法） |
| 2 | **归属确认由客户做，交付人不得代劳** | 归属错 → 全链路结论错（历史"第二套清单"的教训） |
| 3 | **「未启用 / 闲置」必须客户确认后才计入金额** | 试点 / 备用 / 灾备 / 合规留存会造成误判；**不得把试点说成浪费** |
| 4 | **过检签核（交付人 + 复核人双签）** | 单人交付无交叉验证 |
| 5 | **报告每条结论可溯源** | 无法溯源的条目**不得进报告**（9.5 诚实化红线） |
| 6 | **不做「接了再说」的单** | B1 不达标即明示偏差，不粉饰结论强度 |
| 7 | **一个客户只有一个对接人** | 多头口径必然冲突、必然返工 |

## 三、异常处理

| 异常 | 处理 |
| --- | --- |
| 扫描件 / 乱码 | 标「低质量」，**不强行解析**（不猜内容），提示客户补电子版 |
| 文档与现状不一致 | **以客户确认为准**，并标注「文档滞后」——**这本身是一条发现**（文档治理问题） |
| 客户无法确认归属 | 归入「未归属」池，**不参与结论**，在报告列入「待补」 |
| 归属置信 <0.6 且客户不确认 | 标红待确认，**不计入诊断结论** |
| 文档含敏感表（如客户黑名单） | 只学结构、**过滤敏感表**（F16 I-P-O「数据缺失时」） |
| 客户中途改口径 | 记录变更并**重跑受影响环节**；不得"局部打补丁"导致口径不一 |
