# B2 · 诊断交付模板包

> **用途**：避免首次交付靠临场手搓。**原型已实现报告四模式**，本文件说明「每种模式怎么用、给谁看、何时给、必须带什么」。

## 一、四模式报告（同一份结论，四种语言）

| 模式 | 读者 | 用途 | 何时给 | 关键纪律 |
| --- | --- | --- | --- | --- |
| **专业版** | CIO / IT 负责人 | 逐条核对、内部立项 | 诊断完成后**立即** | 每条结论带**溯源**（文档位置 + 置信度）；含**可复算口径** |
| **人话版** | 业务负责人 / 员工 | 看懂「和我有关什么」 | 与专业版**同时** | **不出现内部术语**；措辞柔和（不用「无贡献 / 落后 / 需要激活」类词） |
| **汇报版** | CEO / 董事会 | 汇报与续费谈判 | 年度 / 续费时点 | **一页纸**；**可打印、可转发**；分「年度汇报 / 续费谈判」两种用途 |

**任何模式都不可缺的三段**：

1. **事实基础**——「事实底座」卡（已学习文档数 / 结构化事实条数 / 覆盖系统数 / 结论溯源率）→ 传达「**你拿到的是资产，不是一份报告**」
2. **可对账省钱**——硬三类清单（含「客户已确认 / 已驳回」状态，驳回须填原因）
3. **待你拍板**——明确列出**需要谁决策、决策什么**（避免"报告读完不知道怎么动"）

## 二、硬三类清单模板（表格列定义）

| 列 | 说明 | 必填 |
| --- | --- | --- |
| 类别 | 闲置系统 / 未启用功能 / 手工搬运 | ✓ |
| 对象 | 系统名 / 模块名 / 环节名 | ✓ |
| **事实依据** | 文档位置（哪份文档、哪一节） | ✓ |
| **落差** | 应然（文档说有什么）vs 实然（实际怎么用） | ✓ |
| 年化金额 | 口径 + 计算式（**必须可被客户独立复算**） | ✓ |
| **确认状态** | 待确认 / **已确认** / **已驳回**（驳回填原因） | ✓ |
| 处置动作 | 退订 / 启用 / 集成 / 替换 | ✓ |
| 责任人 | 客户侧负责人 | ✓ |

## 三、落地安排模板（**不做计划管理**）

> **口径**：机会确认（三态）后**直接进入执行档案**——**不做甘特 / 排期 / 里程碑**（PRD 2.10 判据）。落地节奏由客户自定，产品只记录状态与实测结果。

| 项 | 内容 |
| --- | --- |
| **每个机会** | 优先级（ALI / ROI）· 前置依赖 · 责任人 · 预算区间 · **验收标准** |
| **快赢优先** | 至少 1 项**可在 30 天内见效**的（通常是退订 / 启用类）——**这是续费的第一个证据**（属**优先级**，非工期承诺） |
| **不做清单** | 明确写出「本次不建议做的」及原因（**防止小需求被做成大项目**——范围一旦放开，报价与周期都会失控） |

## 四、交付检查单（交付前逐项打勾）

☐ 每条结论可溯源　☐ 硬三类金额可对账　☐ 未启用 / 闲置均已客户确认　☐ 口径唯一　☐ 四模式齐全　☐ 「事实底座」卡已附　☐ 待拍板事项已明确到人　☐ 内部复核双签（B5）　☐ 已标注偏差已向客户明示

## 五、填空示例（以原型演示企业「宁波鑫盛汽车零部件」为例）

> **怎么用**：下面三张表是**已填好的样例**。交付时照这个格式替换成本客户数据即可。
> **关键看两处**：① **事实依据必须写到文档的具体位置**（哪份文档、哪一页/节）；② **金额必须能被客户独立复算**（写出计算式）。

### 5.1 硬三类清单（示例）

| 类别 | 对象 | 事实依据 | 落差（应然 vs 实然） | 年化金额 | 确认状态 | 处置动作 | 责任人 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 闲置系统 | 旧报表系统「报表工厂 v4」 | 《IT 资产台账 2026》P3 | 台账有年费；**流程文档中无任何引用**；近 12 个月无接口调用 | **¥86,000**（= 年费全额） | **已确认** | 退订 | IT · 张工 |
| 未启用功能 | ERP 预算模块 | 《ERP 用户手册 V5》§7.2 | 已购模块「预算管理」；**文档中无使用记录**；现另购专用软件 ¥45,000/年 | **¥45,000**（= 被替代软件年费） | 待业务确认 | 启用模块 + 停用专用软件 | 财务 |
| 未启用功能 | OA 会议室预约 | 《OA 管理员手册》§4 | 功能存在；**无使用记录**（实际用微信群预约） | **¥8,000** | 待业务确认 | 启用 + 发内部通知 | 行政 |
| 手工搬运 | CRM → ERP 订单同步 | 《CRM-ERP 接口说明 v2》P5 | 接口文档**存在**「订单创建 API」；流程步骤标注「**人工导出 Excel 再录入**」 | **¥144,000**（= 600 小时 × ¥240/小时） | 待确认 | 打通接口 | IT + 销售 |
| 手工搬运 | MES → ERP 报工回写 | 《MES 接口文档》P11 | 有接口文档；实际**每日人工汇总录入** | **¥60,000**（= 250 小时 × ¥240/小时） | 待确认 | 打通接口 | IT + 生产 |

**合计：¥343,000 / 年**（闲置 86,000 + 未启用 53,000 + 手工搬运 204,000）
> **注意**：合计**只计「已确认 + 待确认」**，**已驳回项不计**（驳回须填原因，如"该软件为备用系统，季节性启用"）。

### 5.2 执行档案（示例）

| 机会 | 优先级 | 前置依赖 | 责任人 | 预算 | 验收标准 |
| --- | --- | --- | --- | --- | --- |
| 退订旧报表系统 | ALI 高 | 确认无在用 | IT · 张工 | 0 | **年费归零并落账**（台账状态改「已退订」） |
| 启用 ERP 预算模块 | ALI 高 | 财务确认口径 | 财务 | 0 | **停付专用软件 ¥45,000** |
| 启用 OA 会议室预约 | ALI 中 | 无 | 行政 | 0 | 使用率 ≥ 60% |
| 打通 CRM → ERP 订单接口 | ROI 高 | 双方接口联调 | IT | 8-15 万 | **人工录入工时归零**（年省 600 小时） |
| 打通 MES → ERP 报工回写 | ROI 高 | 生产确认字段 | IT + 生产 | 5-10 万 | 年省 250 小时 |
| **不做清单** | — | 上 AI 需求预测：**数据质量 50/100 未达标** | — | — | **本轮不建议**（先补数据，见 AI 就绪度短板） |

> **「不做清单」是必填项**——它防的是「小需求被做成大项目」，也是客户信任的来源。
> **说明**：表中**不设「阶段」与工期**（PRD 2.10：不做计划管理）——落地节奏由客户自定。

### 5.3 汇报版一页纸（示例 · 年度汇报用途）

```
宁波鑫盛汽车零部件有限公司 · 信息化年度汇报

一、IT 全景
   在用系统 7 套 + AI 资产 3 项，年费合计 ¥740,000；核心 ERP / MES / WMS / CRM 已贯通

二、降本成绩（系统体检 · 可对账）
   识别硬三类浪费，保守档年节省 ¥343,000
     闲置系统退订 ¥86,000 / 未启用功能替代 ¥53,000 / 手工搬运消除 ¥204,000
   已决策 3 条（驳回 1 条）

三、优化成效（落地项目 · 取自项目看板）
   （逐项列已上线项目 + 实测节省，非估算）

四、下年计划
   ① 全量系统接入智能问数（员工填表类工作减负）
   ② 采购 / 质量流程 AI 增强
   ③ 持续年度系统体检（循环降本）

事实基础：已学习文档 10 份 · 结构化事实 N 条 · 覆盖系统 10 套 · 结论溯源率 100%
```

> **汇报版与续费版只差第二段与第四段**（年度汇报讲「成绩 + 计划」；续费谈判讲「服务费 vs 已确认节省 + 投入产出倍数」）。

## 六、合规应答版（报告第 4 种模式 · 模板与示例）

> **用途**：审计 / 等保 / 内控时，一份**可直接交给审计方**的权威事实材料。
> **红线（**必须原样保留在材料开头**）**：**只输出文档所述事实，不代替审计结论、不提供数据证据**；**我们不连接业务数据库、不读取任何数据值**（判据见 PRD 2.10）。

### 6.1 五段结构（固定）

| 段 | 内容 | 关键要求 |
| --- | --- | --- |
| **边界声明** | 上述红线原样声明 | **放最前面**，审计方第一眼看到 |
| **一、系统清单** | 名称 / 厂商 / 版本 / 状态 / 负责人 / License 到期 | 与**系统台账真源**一致，不另抄一份 |
| **二、数据流向与集成关系** | K5 集成层：接口对 / 方向 / 字段映射 | **每条附文档出处**；注明"不含实际传输的数据内容" |
| **三、权限与规则** | K6 规则层：审批分级 / 金额阈值 / 权限规则 | 与制度文档一致 |
| **四、溯源与时效声明** | 结论溯源率 100% · 文档时效达标率 ≥85% · 生成时间 | **过期条目须标注**（F16.9） |

### 6.3 交付检查（合规版专用）

☐ 边界声明在开头且未被删改　☐ 系统清单与台账真源一致　☐ 每条数据流向附文档出处　☐ 过期文档已标注时效警示　☐ **未出现任何业务数据值**（客户名 / 金额 / 订单）
> **最后一条是红线**：一旦材料里出现数据值，就等于越过了 2.10 判据——**审计方要数据，应由客户自己提供，不由我们提供**。
