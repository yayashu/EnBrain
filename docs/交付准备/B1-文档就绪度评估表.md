# B1 · 文档就绪度评估表（售前 · 决定是否接单）

> **用途**：客户接洽阶段使用。**10 分钟填完，判断这个客户能不能做、能做出什么质量**。
> **依据**：PRD **F16.5**（文档接入门槛）+ **F16.6.1**（抽取规格，含**第 0 步「文档类型判定」**）+ **1.3 适配前提**。
> **纪律**：**不达标就不接，或明确告知客户"结论会偏弱"**——不做"接了再说"的单（9.5 诚实化红线）。

## 一、硬门槛（任一项不达标 → 不建议接单 / 需商务另行约定）

| # | 门槛 | 判定依据 | 通过 |
| --- | --- | --- | --- |
| 1 | **业务系统 ≥ 3 套** | 少于 3 套时「全量事实」优势不成立（1.3 适配前提） | ☐ |
| 2 | **文档可获取** | 至少拿到核心系统的**用户手册或接口文档**（用户手册优先——K2 功能层只从此类来） | ☐ |
| 3 | **有 IT 对接人** | 能指定**一名**对接人（负责归属确认与答疑，避免多头口径） | ☐ |
| 4 | **文档可解析** | 文档为**可解析格式**（非纯扫描件 / 非加密乱码）、结构完整 | ☐ |

## 二、质量评分（决定"结论强度"，满分 100）

| 维度 | 权重 | 评分口径 | 得分 |
| --- | --- | --- | --- |
| **文档覆盖度** | 30 | 已提供文档的系统数 ÷ 在用系统数 × 100 | |
| **文档类型完整度** | 25 | 每套系统：用户手册 40 + 接口文档 30 + 数据库设计 20 + 制度/SOP 10（多套取均值） | |
| **文档可解析度** | 25 | 可解析（非扫描件 / 非乱码 / 有目录）份数 ÷ 总份数 × 100 | |
| **结构规范性** | 20 | 有目录 / 有版本 / 有条款编号的份数 ÷ 总份数 × 100 | |

**评级与结论口径**：

| 分数 | 评级 | 结论口径 |
| --- | --- | --- |
| ≥ 80 | **A 优** | 可出**完整三类结论**（硬节省 + 机会 + 执行档案），结论强度高 |
| 60-79 | **B 良** | 可出结论，**部分系统结论偏弱**（须在报告标注） |
| 40-59 | **C 可做** | **仅出硬三类中可对账的部分** + 明确列出「因文档缺失无法判断」清单 |
| < 40 | **D 不做** | 建议先做「文档整理」，或改走人工访谈（本产品当前形态不适用） |

## 三、文档类型判定（**F16.6.1 第 0 步** · 逐份填）

> **为什么必须先判类型**：实测发现——**运维 / 部署类文档的标题层级不是功能模块**（40 页样本中 25 页为运维文档，这 25 页的 80 个二级标题里绝大多数是「安装 / 版本 / 容器 / 子模块」；口径与复算脚本见 《[公开文档实测记录](../../experiments/公开文档实测记录.md)》）。**判错类型 → 抽取结果系统性错误**（会抽出上百个假功能模块）。

| 文档 | 类型（勾选） | 可抽层 |
| --- | --- | --- |
| （示例）ERP 用户手册 | ☐ 用户手册 ☐ 接口文档 ☐ 运维部署 ☐ 制度 SOP ☐ 发布说明 | K1 K2 K3 K6 |
| （示例）ERP 接口文档 | ☐ 用户手册 ☑ 接口文档 ☐ 运维部署 ☐ 制度 SOP ☐ 发布说明 | K1 K4 K5 |
| | | |
| | | |

**类型 → 可抽层映射（固定，不得越界）**：

| 文档类型 | **可抽** | **禁止抽** |
| --- | --- | --- |
| **用户 / 操作手册** | K1 · **K2 功能** · K3 流程 · K6 规则 | — |
| **接口 / 集成文档** | K1 · **K5 集成** · K4 数据（字段映射） | **K2 功能模块** |
| **数据库设计** | **K4 数据**（表 / 字段 / 关系；**不学数据值**） | K2 · K3 |
| **制度 / SOP** | **K6 规则** · K3 流程 | **K2 功能模块** |
| **运维 / 部署文档** | K1（系统与部署形态） | **K2 功能模块（严禁）** |
| **发布说明** | 版本时效（供 F16.9 校验） | K2 · K3 |
