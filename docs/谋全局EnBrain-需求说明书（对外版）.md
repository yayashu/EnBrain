## 0. 一页纸

**判断**：企业不缺判断，缺的是**能支撑判断的事实**——文档写着「系统有这个功能」，实际没人用；两者的差，就是可对账的钱。

| # | 三条主张 | 一句话 |
| --- | --- | --- |
| 1 | **一次诊断 · 三条主线** | 事实底座 / 可核验的硬节省 / 可落地的机会，**同一次诊断出齐**，不是三份报告 |
| 2 | **资产优先** | 结论是服务，**事实是资产**：底座留在客户环境，可交接、可自行复算；报告只是它的一次读数 |
| 3 | **同引擎双覆盖** | AI 资产按**系统资产**管理（不建第二张台账、不另立模块），AI 就绪度只是画像的一个维度组 |

**凭什么信（唯一可独立复算的证据）**：40 页公开中文文档实测——**成立 3 条、证伪 1 条**（「标题层级 = 功能模块树」不成立）。结论、证据与复算命令见 [公开文档实测记录](../experiments/公开文档实测记录.md)。证伪一条，比补三条成立更能说明这套方法在做研究，而不是在写方案。

**我们主动放弃了什么**：见 §0.1（八条）。**哪些还没验证**：六项，见 §14.2。

### 0.1 放弃清单：我们主动不做的八件事

| 常见做法 | 我们不做 | 为什么 | 换到什么 |
| --- | --- | --- | --- |
| 访谈 + 顾问经验出报告 | 不靠访谈猜 | 访谈有上限、无法复算，人一走方法就没了 | 结论可复算、可交接 |
| 上一套 BI / 数据中台 | 不碰业务数据 | 碰数据先要过合规与信任关，多数企业第一步就卡住 | 客户敢把文档交出来 |
| 输出落地路线图与排期 | **不做计划管理**（无甘特 / 里程碑 / 进度跟踪） | 排期是项目管理供应商的活，做不好还要担责 | 只对「状态与验收」负责 |
| 报告越厚越显专业 | 一份结论四种语言 | 同一份结论对不同人讲不同话，不是四份报告 | 老板能汇报、员工能看懂、CIO 能核对 |
| 发现问题越多越好 | **允许「未发现重大问题」** | 结论一旦与「问题大小」挂钩，必然诱发夸大 | 结论可信；续费靠资产，不靠惊吓 |
| AI 自动拍板 | 关键结论必须客户确认（三态） | 模型判断不能替客户承担责任 | 客户认账，报告进得了决策会 |
| 一次性交付 | 资产留在客户环境、可重跑 | 结论会过时，事实不会 | 第二年还能用，续费有理由 |
| 各系统各建一本台账 | 一张系统台账 + 一个知识库 | 双源必然漂移 | 改一处、全链生效 |

> 这张表的读法：**看一个方案，先看它拒绝了什么**——拒绝的东西定义了它的成本和立场。

## 1. 背景与问题定义

**企业在系统上的投入持续加码，却始终说不清"这些投入买到了什么、还有哪些还在漏"**——因为**判断一直靠人**（访谈 · 经验 · 汇报），而**事实一直散在几百份文档里，从未有人完整读过**。

**问题因此不在"要不要上 AI"，而在"凭什么判断"**——**凭人说的，还是凭白纸黑字、可核对、可复用的事实**。

### 1.1 结构性缺口：企业的事实底座长期缺位

**企业其实早就买过这套事实**——每套业务系统都配了**全套文档**（从使用说明到二次开发文档），合起来就是该系统「**能做什么、怎么做的、怎么连的、数据怎么存的**」的**说明书体系**（**实际质量参差：缺章、过版、扫描件并不少见**）。**但它从未变成一份底座**——因为**企业内部不存在"完整读过全部"的岗位或流程**：**谁都不缺职责，缺的是一个"读得完"的角色**。

**这是结构性缺口，不是"谁不尽责"**：实施顾问的视野通常限于自己实施的系统；厂商只掌握自己那一套；数字化负责人的精力难以覆盖每套系统的细节；业务部门只熟悉常用模块；外部顾问在 4–8 周内通常只能完成 20–40 场访谈，**注定是抽样**，而且拿到的是"人说的"。**信息分散在组织与厂商之间这件事，换一家咨询公司也不会消失。**

一个典型企业有 **5–20 套**业务系统、累计**数十份文档、数千页**：逐份读完并结构化，**靠人力既不经济也不现实**——**这是时间的物理限制，不是能力问题**。**而这件事恰好不需要人的"抽样"**：机器能**逐份读完、白纸黑字，每条结论都能指到文档段落**；代价是它有一个前提——**文档必须先交全**（缺章 / 过版 / 扫描件需一并说明，见 §13）。

### 1.2 用户侧痛点（五类角色）

| 角色 | 真实处境 |
| --- | --- |
| **企业决策者**（CEO / 总经理） | 知道要降本增效，说不清"哪几个环节最该动"；怕投入打水漂 |
| **数字化 / IT 负责人**（CIO / IT 总监） | 优化优先级难以排序；缺内部立项依据；难以量化收益向管理层汇报 |
| **业务部门负责人** | 不知道自己的流程哪些能优化；改了之后人怎么办；没有可参照的同行案例 |
| **员工**（一线使用者） | 系统怎么用 / 流程怎么走**只能问人**；有改进想法没有出口 |
| **IT / 研发 / 数据**（每天干活的人） | 查一个接口要翻几百页文档；字段在哪个系统哪张表只能问人；**维保 / 验收对账拿不出依据**；人一离职，系统知识就断了 |

**共同点**：不是判断力不够，而是**事实没有被组织起来**。

### 1.3 产品机会与两类结论

**为什么是现在**：① **AI 从"能用"走向"落地"**，而企业侧的真实状态是"**知道重要，不知道从哪开始**"——**窗口开了，判断的依据却还没立起来**；② **降本增效从口号变成考核项**——要的是**能对上账的节省、能落地的结果**，不是又一份报告；③ **政策把"诊断"写成可支付环节**——**需求侧的钱已经在场** ✓。**而"等一等"的代价在变大**：**系统还在增加、文档还在过期**，**越晚整理，事实成本越高**。**三股力指向同一件事：先有一份站得住的事实。**


**机会**：**全量文档学习**——把企业已有的全套系统文档**全部读完** → 构建**可溯源的六层知识**（**K1 系统层 / K2 功能层 / K3 流程层 / K4 数据结构层 / K5 集成层 / K6 规则层**——**它是画像之外的独立知识资产，不进入画像字段**） → 用「**文档说应有**」与「**流程里实际**」的**层间落差**找出浪费与机会。

**产出两类结论**：

| 结论 | 内容 | 特点 |
| --- | --- | --- |
| **可对账的硬节省** | 闲置系统 / 未启用功能 / 手工搬运（**硬三类**） | 金额可由**企业用自己的合同与台账复算**，不依赖信任 |
| **可落地的机会** | 带依据与优先级的候选机会（含"**不建议引入 AI**"的方向） | 业务部门三态拍板；落地后回填实测结果 |

**交付物的性质**：**报告是服务（会过时），事实是资产（只增不减）**。系统升级、组织调整后**不必重做诊断**——更新事实、重跑落差即可。

### 1.4 与既有路径的差别

| | 咨询公司 | 通用 AI 助手 | 数据看板 | **本产品** |
| --- | --- | --- | --- | --- |
| 事实来源 | 访谈 + 顾问经验 | 公开语料 | 企业业务数据 | **企业自有文档（全量 · 逐条可溯源）** |
| 覆盖范围 | 抽样（访谈数量有上限） | 无企业事实 | 仅有数据的环节 | **企业全部业务系统的文档事实** |
| 结论可否复算 | 难 | 不可 | 数字可，口径难 | **可（按同一份文档与台账自行复算）** |
| 资产归属 | 报告归客户，方法不留 | 不涉及 | 数据在客户侧，方法不在 | **事实底座留在客户环境，方法可重跑** |
| 技术中立 | 依赖个人判断 | 不涉及 | 不涉及 | **由结构决定**（不卖系统 · 不做实施 · 不碰业务数据） |

**一句结论**：我们回答"**这个数怎么来的**"，不回答"这个数是多少"。

## 2. 产品定位与理念

**企业真正缺的不是"更聪明的判断"，而是一份站得住的事实**——**判断随人走、随行业变**（换个顾问、换个年份，结论就变），**只有事实留得下来**。

所以这个产品的做法与本类项目相反：**不交付一份更聪明的判断，而是先建一份站得住的事实**（企业自有系统文档 → **逐条可溯源的事实底座**），**再让结论从事实里长出来**——**事实一更新，结论即可重算**；**判断是服务，事实是资产**。

### 2.1 定位与两层理念

**定位**：企业运营优化大脑（**Enterprise Brain**）——以企业自有文档为唯一事实来源，建立**逐条可溯源的事实底座**，据此完成**诊断 · 选型 · 交付**。

**理念的两层（缺一不可）**：

| 层 | 理念 | 回答 |
| --- | --- | --- |
| 上半句 | **以结果为导向** | **为什么做**——赋能 · 降本 · 增效是唯一目的，手段从属于结果 |
| 下半句 | **以全量事实为底座** | **凭什么做**——全套系统文档 → 可溯源事实；落差识别可复算、不依赖专家经验 |

**对外一句话**：**结论会过时，事实不会。**

**产品做四件事**：① **理解**（读全套系统文档与组织数据）② **诊断**（沿价值链定位流程瓶颈与浪费）③ **选型**（六个维度找手段，判断自建 / 采购 / 找第三方）④ **交付**（诊断报告四模式 + 可执行规格：智能化手段给 **Agent Spec**（**智能化方案的机读规格**），非智能化手段给消除 / 配置 / 集成 / 自动化规格）。

### 2.2 AI 原生的五层含义

| 层 | 与传统软件 / 传统咨询的区别 |
| --- | --- |
| **交互原生** | 结构化补齐（缺口点名 + 直接编辑）+ 对话问答；人只做确认与纠偏 |
| **推理原生** | 模型负责**理解、抽取、假设、归因、生成**；**确定性引擎负责评分与测算**——两者解耦，保证结论稳定可复现 |
| **内容原生** | 机会卡 / 工具卡由 AI 起草、人工抽检校准，版本化灰度生效 |
| **交付原生** | 交付**机器可读的可执行规格**，而不是一份 PPT |
| **组织原生** | 事实读取与诊断由系统完成，人只投在**确认与落地**；内容资产跨客户复用，不随客户数线性增长 |

### 2.3 五条信条（取舍标准）

| # | 信条 | 含义 | 落到设计上的机制 |
| --- | --- | --- | --- |
| 1 | **结果优先** | 赋能 · 降本 · 增效是唯一目的，**绝不为用某项技术而优化** | 选型先定维度再定手段；主动输出"不建议引入 AI"的清单 |
| 2 | **全局视野** | 端到端价值链视角，**反对局部次优化** | 落差按价值链环节归位；"瓶颈"一律指"流程与系统衔接上的落差" |
| 3 | **技术中立** | 手段全谱系选型，**AI 是候选不是默认** | 六个维度 × 六种落地方式；推荐必带依据与前置条件缺口 |
| 4 | **AI 原生** | 用 AI 生产这份专业能力，让高质量分析不受专家时间约束 | 确定性计算与生成解耦；内容资产复用 |
| 5 | **资产优先** | **交付的是资产，不是结论**；结论只是事实的一次读数 | 事实与判断分区呈现；事实可导出带走；事实一变即重算 |

> **技术中立不是态度而是结构**：不卖系统、不做实施、不碰业务数据——因此可以给出「**最小可行方案**」，**防止一个很小的功能需求被包装成复杂的大项目**。

### 2.4 边界：三层隔离 · 六条隔离红线 · 三条伦理红线

**三层隔离**（系统纯洁性原则）：

| 层 | 内容 | 是否在本产品领域内 |
| --- | --- | --- |
| **执行层** | 系统改造 / Agent 运行 / 流程落地 | ❌ 边界外（**只出方案与规格**） |
| **逻辑层** | 流程 / 制度 / 规则 / 知识 / 组织智慧 | ✅ 领域内（学习、建模、诊断、推荐） |
| **数据层** | 业务数据 / 系统数据 / 交易数据 | ❌ 边界外（**不读取、不交换**） |

**六条隔离红线（不可妥协）**：

| # | 红线 | 含义 |
| --- | --- | --- |
| 1 | 不直连企业业务系统 | 不做接口对接、不做数据抽取管道、不通过单点登录读写企业系统数据 |
| 2 | 不读取 / 不存储业务数据 | 只提取"逻辑与知识"；接口存在性、字段映射等**结构元数据**属逻辑层（可学），字段的具体业务值（订单 / 金额 / 名单）属数据层（不碰） |
| 3 | 只出方案，不代执行 | 输出优化方案与可执行规格；落地由企业或第三方完成 |
| 4 | 知识与文档严格隔离 | 企业文档与学到的知识**归属该企业**，不用于通用模型训练、不进入行业知识库 |
| 5 | 推荐 ≠ 平台行为 | 报告中的集成 / 自动化建议是对企业或第三方的落地建议，平台自身不做数据交换 |
| 6 | 效果验证不碰数据 | 只采集**人的判断**与逻辑层信息，不读取任何业务系统数据 |

**三条伦理红线（涉及人的数据）**：① 员工贡献与工作复杂度数据**不得用于绩效评价与人事决策**；② 个人维度默认**匿名聚合**展示（业务问答只记频次不记内容、盲区不展示提问人）；③ 个人数据**仅本人完整可见**、可主动共享。

**能力边界**：不提供"派谁做 / 何时做 / 怎么验收"；不含需要经营数据的判断；不承接实施。

### 2.5 手段谱系：六个维度 × 六种落地方式

**第一层：六个手段维度**（先定"从哪个维度优化"）——流程 · 组织与人力 · 系统与数据 · 供应链与运营 · 智能技术 · 业务与商业模式。同一个问题**先在非技术维度找答案**，再谈数字化手段。

**第二层：六种技术落地方式**（S1–S6，再定"以什么方式落地"）：

| 代码 | 方式 | 适用情形 | 可执行交付物 |
| --- | --- | --- | --- |
| **S1** | 消除 | 该环节本身没有价值 | 待消除环节清单 + 影响评估 |
| **S2** | 优化配置 | 规则明确，现有系统即可满足 | 配置与治理清单 |
| **S3** | 集成贯通 | 规则明确、跨系统、已有接口 | 集成方案（系统与字段映射） |
| **S4** | 流程自动化 | 规则明确、高频重复、无接口 | 自动化流程说明 |
| **S5** | 智能增强 | 需理解或生成内容，但须人把关 | 人机分工表 + Agent Spec |
| **S6** | 智能自治 | 知识密集、低风险、可托管 | Agent Spec + 评测集 |

**配套输出（硬性）**：与"建议引入 AI"的清单**并列**，必须同时给出「**不建议引入 AI**」的清单——规则明确的环节直接说明用现有系统配置或自动化即可。

**指标**：**非 AI 方案占比 ≥ 40%**。

## 3. 目标与成功指标（指标唯一真源）

> 这类项目对外**只应当承诺「可核验的交付形态」，不应当承诺「模型分数」**——逐条可溯源（每条结论能指到文档段落）· 硬三类金额可对账（企业拿自己的合同与台账复算）· 报告四模式可整份导出 · **达不到时降级并明示**。**这四项由系统与流程保证、与行业无关，所以敢承诺。**
> **模型能力类数值（准确率 / 完整度 / 忠实度）只给目标值与校准机制**，不写进承诺——它们**取决于客户自己的文档质量与语料**（扫描件 / 过版 / 缺章），**这是项目开始时无法确定的**；未达标时按降级规则呈现、**不阻断交付**（如：画像质量不足 → 结论降级为方向性；引用忠实度不足 → 关键结论强制人工过检签核）。
> 标注「成熟后适用」的指标**均属本期实现**，只是需累积使用数据后才有意义（**不属交付分期**）。

**这四项合起来，承诺的不是"一份报告"，而是一份留在企业自己手里、可以反复读数的资产**——**报告只是它的第一次读数**；**判断会过时，事实不会**。

### 3.1 北极星与产品指标

**北极星指标：有效诊断报告数**——一份报告有效，指它基于企业真实文档、关键字段经用户确认、并通过质量门槛（**低质量报告被系统拦截，不计入数量**）。

| 维度 | 指标 | 目标值 | 判定方式 |
| --- | --- | --- | --- |
| 价值 | 用户认可度（报告有用性评分） | **≥ 4.0 / 5**（UAT 通过门槛 ≥ 3.8） | 用户评分 |
| 价值 | 推荐机会采纳率（标记"会推进"） | **≥ 30%** | 系统回填 |
| 价值 | 报告分享 / 导出率 | **≥ 35%** | 系统统计 |
| 采集 | 采集完成率（填完核心信息） | **≥ 70%** | 系统统计 |
| 生成 | 报告生成成功率 | **≥ 98%** | 系统统计 |
| 价值 | 问题重构采纳率（用户**实际调整方案**） | **≥ 50%** | 行为判定（比"认可洞察"更严） |

## 5. 用户与旅程

**这一章真正要回答的不是"有几种权限"，而是每个岗位上的人缺的那块信息不一样**——所以角色按**关注维度**定义，权限只是它的副产品；旅程则按**一件事从头走到闭环**排（**做 → 交付 → 执行**），不按功能菜单排。**同一个事实底座，五种角色各看各的一面。**

**代价在别处**：五种视图共用一份事实，所以**任何一处事实变了，五种看法都要跟着变**（见 §8 铁律）——**这正是它必须只有一份事实源的原因**。


### 5.1 角色与岗位

**角色 = 关注维度 + 权限（菜单 / 按钮 / 数据范围）**，在「角色与权限」**一处配完**；成员开通账号即按角色自动分配权限与维度。

| 内置角色 | 主要关注 |
| --- | --- |
| 决策者 | 成本与投入产出 · 运营与流程 · 组织与人效 |
| 数字化 / IT 负责人 | 系统与数据 · 成本与投入产出 |
| 业务负责人 | 成本 / 运营（按业务域） |
| 部门管理者 | 执行与协同 · 组织与人效 |
| 员工 | 日常使用（问答 / 我的优化 / 我的建议） |

**岗位 ≠ 角色**：岗位是**只读的组织属性**（由 HR / 组织导入，系统不提供岗位字典与维护入口），仅用于**三项用途**——知识与经验的业务聚合（岗位赋能包 / 知识盲区 / 经验池）· 匿名聚合单元（企业视角以岗位为锚点，如"客服专员 ×3"）· 个人画像的职能锚点。**岗位不参与权限、不产生维度、不做组织树节点**；未导入岗位的客户**按部门回退**。

### 5.2 企业级旅程（**E1–E6：一次诊断六步** · **D1–D10：深度诊断链路**）

**产品有两条前后相接的链路**：

**第一段 · 一次诊断六步（E1–E6）**——一次跑完、一次出两类结论：

| 步 | 环节 | 人工参与 | 产出 |
| --- | --- | --- | --- |
| **E1** | 文档接入与归属 | 对接人按系统维度批量确认（低置信逐条确认） | 事实来源清单 |
| **E2** | 知识抽取 | 交付人抽检覆盖全部低置信项 | 可溯源事实库（K1–K6） |
| **E3** | 时效校验 | 对接人确认文档对应当前版本 | 时效标注（待核实项） |
| **E4** | 落差识别 | 各系统负责人**逐条确认**并签核 | **硬三类清单（含金额与出处）** |
| **E5** | 机会匹配 | 业务部门排序取舍确认 | 候选机会集（带依据与优先级） |
| **E6** | 方案与交付 | 交付人与复核人双签 | 报告四模式 + 执行档案 + 资产导出 |

**第二段 · 深度诊断链路（D1–D10）**——在第一段发现之上展开：

| 环节 | 系统做什么 | 人做什么 |
| --- | --- | --- |
| **D1 战略对齐** | 对齐关键约束（合规 / 数据出域 / 预算 / 决策链）；"关注视角"可选勾选（不勾选也出全量报告） | 确认约束（视角可选） |
| **D2 采集理解** | 文档学习 + 缺口点名 + 实时回填 | 上传文档 · 批量确认归属 · 纠偏 |
| **D3 画像确认** | 生成画像卡与自建能力评估，区分"已确认 / 系统推断" | 一键修正 |
| **D4 流程梳理与诊断** | 还原 AS-IS 流程树，标注四类浪费并折算年化成本 | 确认还原结果 |
| **D5 优化设计** | TO-BE + 手段域选型（S1–S6）+ "不建议引入 AI"清单 | 候选机会排序取舍 |
| **D6 资源选型** | 匹配实现资源与适配度、成本量级 | 拍板选哪家 |

| **D8 机会确认与纳入** | 三态判定（成立并落地 / 方案需调整 / 不成立 + 结构化理由） | 业务部门拍板 |
| **D9 交付物生成** | 报告（人读）+ 可执行规格（机读） | 导出 / 分享 |
| **D10 落地闭环**（可选） | 落地完成 → 未变更直接闭环 + 写实测 ROI；有变更额外沉淀落地方法入经验池 | 点"落地完成" |

### 5.3 个人级旅程

员工侧是企业级旅程的**轻量版**（无需排期、无需填报，在日常对话中完成），也是**使用频率最高**的主线：

日常问答（答案附来源，答不上记入知识盲区）→ 一句话描述工作（访谈式追问，**每轮只问 1 个问题**）→ 个人工作画像 → 优化路径（**A / B / C / D 分级**：A 个人可落地 / B 需部门支持 / C 需 IT 支持 / D 需企业决策）→ 实施（B / C / D 一键转提交，默认匿名）→ 回填成效（累积个人成长档案）。

**双闭环**：个人级闭环沉淀的流程事实与实践经验**自下而上回流企业画像**，与企业级"自上而下"互补。

**信任边界**：个人画像与优化记录**默认仅本人可见**；工作复杂度数据**只用于优化，禁止用于绩效考核或工作量评估**；转提交默认匿名。

### 5.4 人机分工总则

**人只做三类事**：**确认**（归属 / 时效 / 落差逐条）· **拍板**（约束 / 画像 / 选型与交付方式 / 机会三态）· **提供私有资料**。

**其余由系统完成**。三处质量门：**抽检门**（E2 抽检必须覆盖全部低置信项）· **确认门**（E4 逐条签核，未确认条目不进入结论）· **双签门**（E6 复核不通过不交付）。

## 7. 功能需求（模块卡）

> 这套能力**不是一堆功能的加总，而是一条链**——**事实（读全）→ 结论（诊断）→ 方案（选型）→ 交付（闭环）**；链上每一环都**单独可核**（可溯源 · 可对账 · 可降级），**所以哪一环断了，读者当场能看出来**。
> 每张卡因此只回答五件事：**为什么存在**（目的）· **靠什么跑起来**（主流程）· **什么绝不能违反**（关键规则）· **不做什么**（边界）· **怎么算达标**（验收要点 + 规格范围）；并配「本模块人机分工」表（输入 / AI 完成 / 人工干预 / 输出 / 数据缺失时）。
**代价是文档更长**——每张卡都要写清"不做什么"；但这换来**研发不必猜**：**含糊的边界最后都会变成返工**。


### 7.1 主线

#### 7.1.1 文档事实引擎（F16 · 核心主线）

- **目的**：把企业所有业务系统的文档**全部读完、结构化、可溯源**，产出 K1–K6 六层事实与硬三类发现——**这是产品的资产本体**，后续所有结论都从这份事实里长出来。
- **主流程**：上传（**无需预先整理或打标签**）→ 分类与归属（类型 + 归属系统 + 置信度）→ 解析（OCR / 文档解析）→ 抽取（系统 / 流程 / 角色 / 规则）→ 质量校验 → **按系统维度批量确认** → 去重合并入库 → 层间落差识别（硬三类）→ 时效校验 → **事实一变即重算**。
- **关键规则**：① 每条知识携带**来源文档与段落位置**；② 归属置信 **< 0.6 → 标红待确认，不强行归属**；扫描件 / 乱码 → 标"低质量"，**不强行解析**；③ **纠偏统一在文枢智库**（知识条目是全站结论的唯一底座）；④ **知识同生同灭**——文档删除或密级变更，派生知识同步清除 / 同步变更；⑤ 重算为事件驱动（台账变更 · 文档换版 · 组织调整），**不依赖人工发起一次诊断**。
- **边界**：只学**结构元数据**（系统名 / 功能 / 流程步骤 / 角色 / 接口 / 规则），**不学业务数据值**；**不建"敏感数据检测"能力**（学习范围既定不含业务数据，再建即过度设计）；系统资产归属**以系统台账为准**（不建第二套台账）；上传方对所传文档不含业务数据值负责，**系统不承担识别义务**。
- **验收**：可溯源率 **100%** · 抽取准确率 **≥90%** · 文档覆盖度 **≥80%（核心 100%）** · 六层完整度分层达标 · 抽检覆盖全部低置信项。
- **规格范围**：文档分类与归属 · 六层抽取 · 质量校验 · 时效校验 · **文档就绪度评估**。

#### 7.1.2 诊断引擎（F5 · 核心主线）

- **目的**：**先找病根，再开药方**——回答"企业真正的病根是什么"，而不是做"机会库匹配器"。
- **主流程**：假设生成（3–5 个核心问题假设 + 证据强度）→ **根因归因**（根因树：先验 × 后验，封闭集合）→ **问题重构**（最可能根因 ≠ 用户自述痛点时）→ 机会匹配（规则硬过滤 → 向量召回 → LLM 补充，三层）→ **ALI（优化杠杆指数）评分**（价值 / 可行 / 风险，纯函数）→ 四象限视图。
- **关键规则**：① 根因**仅从封闭集合中选择**，不允许自由生成；② 证据必须能**程序化映射**至事实字段；③ **置信度由规则计算，不由模型评分**；④ 低置信结论**必须经用户确认**方可进入关键结论（三级：≥0.85 / 0.60–0.85 / <0.60）。
- **边界**：不产出"愿望型指标"（无依据的优化项）；**评分与测算不交给 LLM**。
- **验收**：关键结论**全部经用户确认**；客户对根因结论的认可率纳入 UAT 统计。
- **规格范围**：假设生成 · 根因归因 · 问题重构 · 机会匹配 · ALI 评分。

#### 7.1.3 流程梳理与优化设计（F6 · 核心主线）

- **目的**：还原 AS-IS 流程、量化四类浪费，并给出 TO-BE 与**全维度手段选型**。
- **主流程**：流程还原（可上传 SOP / 流程图增强）→ 浪费识别与量化（搬运 / 等待 / 重复决策 / 返工）→ 手段分级与选型（六个维度 × S1–S6）→ TO-BE 与人机分工 → 交付物。
- **关键规则**：**流程侧四类与知识侧六类不混用**（判据不同、可能重叠，**同一处只计一次**）；"瓶颈"一律指**流程与系统衔接上的落差**。
- **边界**：不做产能 / 库存类经营瓶颈判断（需经营数据）。
- **验收**：浪费量化可展开查看计算过程。
- **规格范围**：流程还原 · 浪费量化 · 手段选型 · TO-BE 与人机分工。

#### 7.1.4 机会确认与落地闭环（F19 · 核心主线）

- **目的**：把结论变成可盯的落地——**确认 → 执行 → 实测回填**。
- **主流程**：三态确认（成立并落地 / 方案需调整 / 不成立）→ 进入执行档案 → 状态更新与效果验证 → **实测 ROI 回填** → 闭环（未变更直接闭环；有变更额外沉淀落地方法入经验池）。
- **关键规则**：① **"不成立"必须给结构化理由**（否则无法反哺规则校准）；② **确认后 90 天无动作自动衰减**（防僵尸机会堆积）；③ 落地只做**轻量记录**。
- **边界**：**不做计划管理**（无甘特 / 排期 / 进度跟踪）、**不做验收**；不负责偏差数值计算本身。
- **验收**：执行档案状态可查；实测 ROI 可回填并用于校准机会卡。
- **规格范围**：三态确认 · 执行档案 · 效果验证 · 实测 ROI 回填。

#### 7.1.5 履约核查（F23 · 核心主线）

- **目的**：从"发现差距"到"**拿出可核对的材料**"——承诺 vs 实际。
- **主流程**：按系统聚合差距 → 差距初判与三分归因 → **两级清单**（1 级系统汇总 / 2 级差距明细）→ 双向证据与**客户确认闸门** → 导出谈判材料（单系统 / 整套）。
- **关键规则**：① **不带金额**（无法按项拆分）；② 1 级不带确认动作（防误操作）；③ **客户未确认的差距不进入材料**；④ 材料与"合规应答包"同源。
- **边界**：不代替审计结论、不提供数据证据；不对接业务系统；不自动对外发函；**整改要求与跟踪本期不做**（交涉在系统外完成）。
- **验收**：两级清单可搜索 / 分页（千级形态）；导出可用。
- **规格范围**：差距聚合 · 三分归因 · 两级清单 · 客户确认闸门 · 材料导出。

#### 7.1.6 报告与交付物（F8 · 核心主线）

- **目的**：**唯一交付出口**——同一份结论换四种语言。
- **内容**：**四模式**——**专业版**（完整长文档，可通读 / 页内检索 / 整份打印）· **人话版**（一页讲清楚）· **汇报版**（决策层材料，含用途切换）· **合规应答版**（审计 / 等保 / 内控）；导出 PDF（整份）/ Word / PPT；分享链接。
- **关键规则**：① 报告正文**只做表述组织、不产生新事实**——每个论断挂来源类型（事实 / 客户确认 / 推断 / 洞察），**事实与判断分区呈现**；② 章节编号由结构生成；③ 报告末尾给"下一步"出口（工作台 / 执行档案）。
- **边界**：不承接实施；不承诺"报告里的机会一定省钱"（给的是依据与方向）。
- **验收**：**可整份导出**；事实性错误 ≤1 处 / 份、关键结论 0 处。
- **规格范围**：报告四模式 · 来源标注 · 章节生成 · 导出与分享 · 报告页交互。

#### 7.1.7 员工知识助手（F20 · 核心主线）

- **目的**：员工侧的**日常入口**——问答 + 个人流程优化 + 岗位赋能与经验沉淀。
- **主流程**：日常问答（答案**附来源**；答不上记入知识盲区）→ 访谈式梳理（**每轮只问 1 个问题**）→ 个人工作画像 → 优化路径（**A / B / C / D 分级**）→ 一键转提交（B → 建议，默认匿名；C / D → 优化项目）→ 回填成效（个人成长档案）。
- **关键规则**：① 个人画像与优化记录**默认仅本人可见**；② 工作复杂度数据**只用于优化，禁止绩效与人事决策**；③ 信息不足时**继续追问，不给半成品画像**；④ 岗位赋能包＝"必须掌握"清单（**文档 + 章节锚点**）。
- **边界**：不做通用办公助手 / 个人 Copilot。
- **验收**：问答可溯源率 100%；意图识别 ≥92%。
- **规格范围**：日常问答 · 访谈式梳理 · 个人画像 · 优化路径 · 岗位赋能 · 经验条目。

### 7.2 支撑

#### 7.2.1 画像补全与实时共建（F1 · 支撑）

- **目的**：让画像**尽快成型且可随时纠正**（诊断质量 = 画像质量 × 引擎质量）。
- **范式**：**预填优先 · 编辑为主 · 缺口点名补缺**（"说 → 抽取 → 确认"式的对话采集高密度结构化数据是**反模式**）。
- **关键规则**：① 派生字段**只读**（在用系统清单由系统台账派生、部门与人数由组织树派生）；② 人工动作是**纠偏**（划掉 / 改值）而非填空；③ 输入只有两条来源：**文档与组织数据自动获取**（**C6 资产导入** + 文档学习反哺）与 **IT 人工填报**。
- **边界**：不采集业务数据值（入口明示先剔除业务数据列，**不建自动识别能力**）；C6 只采逻辑层信息（预算 / 成本区间）。
- **验收**：采集完成率 ≥70%；**关键字段强制确认**后方可出正式结论（PQS < 50 拦截、50–70 降级）。
- **规格范围**：采集通道 · 字段级规则 · 缺口点名 · 预填规则 · 自助修正。

#### 7.2.2 实时企业画像（F2 · 支撑）

- **目的**：八维画像的**可视化 · 快照 · 可复现 · 导入导出**。
- **关键规则**：① 每字段携带**来源 + 置信度 + 证据原文**三元组；② 写回真源即触发全链路重算（画像变，全链路重算）；③ 导入 / 导出（Excel / JSON / 一页纸画像卡）。
- **边界**：**不做系统直连**（文件 / 表格导入）。
- **验收**：PQS 达标率 ≥85%；"只看 AI 推断项"可一键纠偏。
- **规格范围**：八维字段 · 来源与置信 · 快照 · 导入导出 · 变更传播；字段定义见 §8.1。

#### 7.2.3 机会库（F4 · 支撑 · 核心资产）

- **目的**：机会卡**内容资产**。
- **规模**：**本期制造 2–3 行业 × 硬三类对应机会 = 80 张**；每卡标注「手段域 + S1–S6」。
- **关键规则**：① 最小单元是「**流程优化机会**」，不是「AI 场景」；② 生命周期状态机（草稿 → 上线 → 降权 → 下架）；③ **抽检 ≥ 20%**（关键结论 ≥ 10%）。
- **边界**：机会卡字段必须可溯源。
- **验收**：字段完整、抽检达标；采纳率 ≥30%。
- **规格范围**：机会卡字段 · 触发规则 · 生命周期 · 抽检与降权 · 反馈回流。

#### 7.2.4 ROI 与价值测算（F14 · 支撑）

- **目的**：把价值**算清楚、可复算**。
- **关键规则**：**纯确定性与纯函数**（禁止 LLM 参与）；输出三档区间（保守 / 中性 / 乐观）+ 敏感性；参数全透明可调、来源标注。
- **边界**：不含经营数据类收益；预估须与实测回流校准。
- **验收**：计算过程可展开；ROI 偏差先记基线。
- **规格范围**：参数体系 · 三档区间 · 敏感性 · 计算过程展开。

#### 7.2.5 工具与实施资源库（F12 · 支撑）

- **目的**：为"**推荐以何种能力落地**"提供依据。
- **关键规则**：评分维度公开 · 多候选并列 · **无商业关系**（不代理 / 不收佣金 / 不排出价榜）；工具卡标注"最后更新时间"，超期未复核自动降权。
- **边界**：不替客户选型（只给候选与适配度）。
- **规格范围**：工具卡字段 · 评分维度 · 有效期与降权 · 用户纠错。

#### 7.2.6 资源匹配与交付方式（F13 · 支撑）

- **目的**：回答"**自己做、买，还是找人**"。
- **内容**：**三种交付模式**——A 自建（Build）· B 采购（Buy）· C 第三方（Partner）；用 **C（自建能力）× X（场景复杂度）** 的确定性模型判定；输出**判定 + 依据 + 备选与代价** + 资源包（角色类型 / 人天区间 / 预算量级 / 筛选标准 / 评标表 / POC 方案）。
- **关键规则**：① 只出**建议**，决策权在人；② 资源包为**量级参考，非排期**；③ 自建能力数据不足时**保守推荐第三方 / 采购**（自建失败成本远高于采购）。
- **边界**：平台不参与实施、不因商业合作倾斜推荐。
- **规格范围**：判定模型 · 资源包构成 · 备选与代价 · 评标表与 POC。

#### 7.2.7 角色、权限与协作（F11 + F9 · 支撑）

- **目的**：**一处配完角色**，权限在界面真实生效。
- **内容**：角色对象 = 关注维度（内容轴）+ 菜单权限 + 按钮权限 + 数据范围 · 席位与账号 · 文档与知识可见性（文档级）· 操作日志与审计 · **协作**（评论 / @ / 通知偏好 / 并发编辑冲突的乐观锁处理）· 通知与消息中心。
- **关键规则**：① **三项权限必须界面真实生效**（导航过滤 / 函数级拦截 / 列表真实过滤）——**不做"配置存在但界面无反应"的假承诺**；② 权限与文档密级叠加时**取最严**；③ **权限不交给 AI**（安全边界）；④ 跨主体数据默认隔离，集团内对标需**显式授权**。
- **边界**：运营后台功能不授予任何客户侧角色。
- **验收**：**切换角色即可实测**三处差异（导航 / 按钮 / 列表）。
- **规格范围**：角色对象 · 三项权限生效 · 文档可见性 · 审计日志 · 协作与通知。

#### 7.2.8 企业档案与主数据（F18.6–F18.8 · 支撑）

- **目的**：为全站提供**主数据真源**（被 8 个以上模块引用，是事实与权限的地基）。
- **内容**：**系统台账**（系统资产**唯一真源**：登记 / 编辑 / 导入导出 / 到期决策 T-60 / 退订落账）· **组织架构一棵树**（**Tenant 企业空间** → **OrgUnit 经营主体** → 部门 → 人员 + 账号）· **岗位导入**（只读）· **职员与账号**（账号开通与停用的唯一入口 · 席位联动）。
- **关键规则**：① 画像中的系统 / 人数等字段**由本模块派生**，画像侧只读；② 席位超限**阻断新开通并引导升级**；③ 台账变更 → 关联知识标"待重新校验"。
- **边界**：**不做系统直连**（一律文件 / 表格导入）。
- **验收**：千级形态查询（多关键词 + 状态筛选 + 排序 + 分页）；导入保留原有关联关系。
- **规格范围**：系统台账字段 · 到期决策 · 组织树 · 岗位导入 · 账号与席位。

#### 7.2.9 行业知识库（F3 · 支撑）

- **目的**：提供**行业基准参数 · 根因库 · 行业模板**，支撑 ROI 与诊断推理。
- **关键规则**：① 每个参数**必须标注来源与置信度**；② 无实测基准时用相邻行业或通用基准兜底，**必须标注"参考值，非本行业实测"**，不得伪装成本行业数据；③ 随客户实际回填持续校准（数据飞轮）。
- **边界**：不做行业经营数据判断。
- **规格范围**：行业参数表 · 根因库 · 机会模板 · 来源与置信标注。

## 8. 公共对象与真源

**产品能不能被信任，前提是：结论都能倒推回去**——所以画像不是"一张数据表"，而是**唯一事实源**：每个字段都带**值 + 来源 + 置信度 + 状态**，报告里每一句都能指回它的出处；**不存在绕过画像的输入通道**。

### 8.1 画像（唯一事实源）

**定义**：八维画像 × 四层成型（**L0 身份 → L1 能力 → L2 流程 → L3 意图**）；**每个字段必须携带四要素**——**值 + 来源 + 置信度 + 状态**（并保留证据原文）。

**三条架构铁律**：① **一切从画像派生**（机会匹配、流程诊断、评分、ROI、选型、交付决策、报告、可执行规格**全部以画像字段为唯一输入**，不存在绕过画像的输入通道）；② **画像变，全链路重算**（不允许任何模块缓存与画像不一致的旧结论）；③ **画像字段 = 数据契约**（字段新增 / 变更必须评估下游影响，每个字段声明"驱动哪些结论"）。

**质量门（PQS，画像质量评分）**：

| PQS | 处置 |
| --- | --- |
| **≥ 70** | 可用 |
| **50–70** | **结论降级**：只给方向与粗估区间（不给精确 ROI 与交付决策），强提示需补充的字段 |
| **< 50** | **拦截**：不生成正式报告，仅输出"行业速览 + 待补字段清单" |

**五类关键字段强制确认**（未经确认只能产出"预览级"结论，不得写入正式报告）：行业与细分 · 员工 / 营收规模 · 核心业务流程 · 已知痛点 · 在用系统清单。

**派生字段只读**：在用系统清单 → 由**系统台账**派生；部门与人数 → 由**组织树**派生（界面上标注"只读，去 X 修改"）。

**维护处**：7.2.1（补全范式）· 7.2.2（实时与快照）。

### 8.2 机会卡与经验条目

**机会卡（Opportunity Card）**——最小单元是「**流程优化机会**」而非「AI 场景」：

| 要素 | 说明 |
| --- | --- |
| 标识与归属 | 唯一标识 · 机会名 · 业务域 |
| 适用条件 | **触发规则表达式**（行业 / 规模 / 系统 / 流程 / 痛点） |
| 手段标注 | **手段域** + **技术落地方式（S1–S6）** |
| 现状与目标 | AS-IS 流程 → TO-BE 流程 |
| 价值与实施参数 | 价值参数（节省比例 · 参与人数）· 实施参数（周期 · 人天 · 难度）· 风险等级 |
| 证据与质量 | 行业案例（脱敏）· 卡质量分（回流校准） |

**规模与生命周期**：本期 **80 张**（制造 2–3 行业 × 硬三类）；状态机 **草稿 → 上线 → 降权 → 下架**。**定义处**：7.2.3。

**经验条目（第 7 类知识资产）**：来源五类——① 成长档案"已落地"回填沉淀 ② 献策采纳沉淀 ③ 微调研反馈 ④ 手动提交 ⑤ 落地闭环沉淀（有变更时）；**默认匿名聚合、不得用于绩效与人事决策**。**定义处**：7.1.7（F20.7）。

### 8.3 角色与权限（三套词汇收敛为一套）

| 概念 | 定义 | 是否决定权限 |
| --- | --- | --- |

### 8.4 版本与快照

**统一口径**：**快照 = 某一时点的事实 + 由它得出的结论**。由此派生三处用法：**画像快照**（可复现、可对比差异）· **报告版本**（绑定生成时的画像快照，可一键"基于新画像重新生成"）· **企业全景的版本与快照**（第 N 次 vs 第 N+1 次对比）。

**LLM 职责边界（硬性）**：

| 交给 LLM | 交给确定性引擎 |
| --- | --- |
| 理解与抽取 · 假设生成 · 根因归因的候选 · 文案组织 · 规格起草 | **评分 · ROI · 交付方式判定 · 去重与冲突取舍 · 置信度计算** |

**四条实现纪律**：① **结构化输出强校验**（字段类型与枚举；失败时**携带错误信息重试**，上限 2 次，超限降级为规则模板或转人工——**不做无信息重试、不无限重试**）；② **降级链路**：强模型不可用 → 弱模型 → 规则 / 模板兜底，并向用户明示"当前为简化模式"；③ **置信度由规则计算、分三级**（**≥ 0.85 高 / 0.60–0.85 中 / < 0.60 低**，低置信不出确定性结论）；**LLM 永不自报置信度**；④ **报告正文转写**：不产生新事实，论断挂来源类型，事实与判断**物理分区**。

**必须拒识的场景（硬性）**：5 类关键字段未确认 · PQS < 50 · 机会库无匹配场景 · ROI 参数缺失过多 · 规格依赖信息不足 · 用户问题超范围——一律**说明原因并给出补充路径，禁止编造**。

**持续学习与治理**：提示词 / 模型 / 机会卡 / 权重全部**版本化**；任何变更必须过回归且**指标不下降**才允许发布；灰度 5% → 20% → 100%；一键回滚 ≤5 分钟；Embedding 与索引**一并版本化**。

### 10.3 安全合规与伦理

- **边界与红线**：见 **§2.4**（三层隔离 · 六条隔离红线 · 三条伦理红线）；
- **工程机制**：输入过滤 + 输出校验 + 系统提示词隔离（防注入 / 越权）· **生成内容明确标识** · 日志**追加写入、不可篡改、可导出** · 任何结论支持**申诉与人工复核**；
- **合规资质目标**：等保三级 · ISO27001（逐步）。

### 10.4 数据生命周期

| 层 | 处置 |
| --- | --- |

## 11. 技术架构与部署

**架构由边界决定，不由技术偏好决定**——**不直连业务系统 · 不读业务数据 · 只出方案不代执行**，因此**本地化部署、不依赖专有数据、不做实时集成**；**代价**是**事实更新靠客户重新交文档**（对策见 §13）。

### 11.1 分层

| 层 | 内容 |
| --- | --- |
| 界面层 | Web 应用（本期仅 PC Web） |
| 服务层 | 作业编排（E 链路）· 任务调度 · 权限 · 报告服务 · 规格生成 |
| 事实与识别层 | 文档解析 → 事实抽取（K1–K6）→ 落差识别 → 时效校验 |
| 数据层 | 关系型数据库（业务 + 知识条目）· 向量检索 |
| 外部服务 | 模型网关（多厂商分级路由）· 文档解析服务 |

### 11.2 处理链路

```
文档（多种格式）→ 文本抽取（保留页码与段落号）→ 分块（每块带来源锚点）
 → 结构化抽取（按事实类别输出结构化结果 + 来源锚点）
 → 事实校验（与系统台账交叉，打置信度）→ 入库（事实库）
 → 层间落差识别（确定性规则）→ 时效校验 → 结论与报告
```

### 11.3 关键设计点

1. **确定性链路与生成链路分离**——评分 / 金额 / 交付方式为**纯函数**，与模型解耦，可单独测试与审计；
2. **成本可控**——抽取与分类用成本较低的模型、生成用能力更强的模型；**单份交付成本设硬上限**并按租户拆分统计；
3. **配置化与灰度**——提示词 / 权重 / 阈值**不改代码**即可发布；支持灰度与特性开关；
4. **可执行规格以 YAML 为中间表示**，各平台适配器从中间表示转换——**避免被单一平台锁定**；
5. **全流程埋点 + 人工抽检队列**——自动化率提升的同时质量不下降。

### 11.4 部署形态

| 形态 | 说明 | 本期 |
| --- | --- | --- |
| **本地化 / 私有化** | 单实例独立部署 · 数据不出域 · 容器化交付 · 支持离线模型 | ✅ **交付形态** |
| 公有云多租户 | 多租户 + 逻辑隔离，面向腰部及以下客户 | 架构预留 |
| 混合 | 事实在本地、模型与算力在云端（脱敏后） | 架构预留 |

**同一套代码支持三种形态**（配置切换，不为形态维护多套版本）；**运营后台归交付方、不在客户域内运行**。

## 12. 本期验收

**验收不靠"看演示"，靠"你自己能用起来"**——**知识查得到 · 金额算得出 · 改动有依据**；交付物与判据都是**可核对的**：**查不到、算不出、用不上的，都不算通过**。

**代价**：验收要客户在场、要拿原始文档，**因此更慢**——换来的是**结论不靠演示、不靠解释**，**并且是客户自己动手验过的**。


### 12.1 交付物清单

| 类 | 交付物 |
| --- | --- |
| **系统** | 本地化部署实例 + 离线模型 · 操作手册与培训材料 |
| **结论** | 诊断报告四模式 · 硬三类清单（含金额与出处）· 候选机会集 |
| **资产** | 事实底座导出 · 岗位赋能清单 · 履约核查清单 · 执行档案 |
| **工程** | 需求规格 · 接口文档 · 数据字典 · 标注规范 · 模型卡片 · 提示词文档 · 评测报告 · 运维手册 |

### 12.2 验收口径

| 项 | 标准 | 判定方式 |
| --- | --- | --- |
| **事实准确性** | 清单类事实准确率 **≥ 90%** | 抽检（**必须覆盖全部低置信项**） |
| **可溯源率** | **100%** | 自动检查 + 抽检 |
| **未启用候选的客户确认率** | **≥ 70%** | 客户认可"确实未在用"的比例；低于该值时对该客户**不出未启用结论**并明示覆盖不足 |
| **引用忠实度** | **≥ 95%**（校准后的正式指标） | LLM-as-judge + 专家抽检 ≥10% |
| **权限与治理** | 菜单 · 按钮 · 数据范围三处在界面真实生效 | **切换角色即可实测** |
| **交付形式** | 报告可整份导出（PDF / Word / PPT） | 导出实测 |
| **UAT** | 报告有用性 **≥ 3.8 / 5（通过门槛）**，目标 ≥ 4.0 | 种子企业真实使用 |

### 12.3 测试与验收方法

| 类型 | 内容 | 通过标准 |
| --- | --- | --- |
| 功能测试 | 采集 / 画像 / 诊断 / 报告 / 导出 | 用例通过率 100% |
| **AI 输出质量评测** | Golden Set 回归（§3.2 全部指标） | 全部达标 |
| **提示词回归** | 每次提示词 / 模型变更跑回归集 | 指标不下降 |
| **拒识与降级测试** | 构造低置信 / 超范围 / 服务不可用场景 | 按 §10.2 正确响应 |
| **安全与内容安全测试** | 提示词注入 · 越权访问 · 跨企业隔离 · 生成违规内容 | 无成功攻击；拦截率 100% |
| 性能测试 | ① **对象分离**（确定性链路与异步链路分开测）② **场景**（单企业满载 / 多企业并发）③ **采样**（50 分位与 **95 分位**，承诺口径按 95 分位）④ 达标即为基线，未达标触发降级 | 达 §3.4 |

### 12.4 评测集要求

- 覆盖**制造 2–3 行业 × 每行业 ≥3 家企业画像** + 专家标注的期望输出；
- **标注独立性（硬性）**：标注人须为**独立行业专家**（不属产品 / 算法 / 运营团队），标注前不接触产品输出，并记录标注者与时间；
- **一致性准入**：机会排序以专家排序 **Kendall's τ ≥ 0.7** 为准；低于阈值先修标注规范；
- **触发规则**：任何提示词 / 模型 / 机会卡 / 权重变更，必须过回归集且指标不下降方可发布。

## 13. 风险

**风险不在技术侧，而在配合与付费侧**——技术是成熟组合，真正的变量只有两个：**客户愿不愿意把文档交全**、**愿不愿意为资产持续付费**。对策因此集中在两处：**降低配合成本**（缺口点名 / 分组渐进 / 断点续填）与**不达标时的降级路径**（见 §3）。

| # | 风险 | 影响 | 对策 |
| --- | --- | --- | --- |
| 1 | **用户不愿填完长表单**（采集流失） | 高 | 缺口点名 + 分组渐进 + 行业默认值推断 + 断点续填 + 进度预期管理 |
| 2 | **动机冲突**（结论与"发现问题的大小"挂钩，可能诱发夸大） | **高** | ① **允许并交付"未发现重大问题"的结论**；② **盲抽检**（对已确认结论做独立抽检）；③ **金额三层纪律**（推断值不计入可核验）；④ 客户确认率与误报率**纳入内部考核**（不是"发现越多越好"） |
| 3 | **画像推断错误导致整份报告跑偏** | **高** | PQS 质量门槛（<50 拦截 / 50–70 降级）+ 5 类关键字段强制确认 + 来源与置信度全透明 + "只看 AI 推断项"快速纠偏 |
| 4 | **AI 生成内容的事实性错误** | 中 | 关键结论必须可溯源；**无来源内容不得进入报告正文**；报告事实性错误 ≤1 处 / 份、关键 0 处 |
| 5 | **ROI 测算被质疑"拍脑袋"** | 高 | 参数全透明可调 + 三档区间 + 来源标注 + 行业基准值来源明示 |
| 6 | **机会库质量不足、推荐泛泛** | 高 | 机会卡强制字段 + 行业专家评审 + 用户反馈回流闭环 + 超期降权 |
| 7 | **工具推荐的中立性受质疑** | **高** | 评分维度公开 · 多候选并列 · **无商业关系**（不代理 / 不收佣金 / 不排出价榜）· 用户纠错入口 |
| 8 | **合规与数据敏感（客户不敢交文档）** | 中 | 只读文档不碰业务数据 + "不留存"选项 + 本地化部署 + 审计留痕（§2.4） |
| 9 | **员工贡献 / 工作复杂度被滥用** | **高（伦理）** | 纳入"**不得用于绩效与人事决策**"红线；匿名聚合；聚合阈值（少于 5 人的部门 / 岗位不展示个人维度）；申诉通道 |
| 10 | **员工不知情地被"监控"的抵触** | 中 | 定位为**减负**而非考核；界面明示"本视图用于帮你减负，不用于任何评估"；提供变革管理提示 |
| 11 | **用户期望"AI 全自动包办"** | 中 | 明确承诺边界：我们产出方案与规格，**实施责任在企业或第三方**（用"资源包"把责任讲清楚） |
| 12 | **提示词注入导致跨企业数据泄露** | **高** | 输入过滤 + 输出校验 + 模型网关层系统提示词隔离 + 禁止将其他企业数据带入上下文 + 审计日志 |
| 13 | **企业文档误含业务数据值** | 中 | **输入契约**（学习范围＝系统文档，不含业务数据值）+ 入口边界提示 + 可彻底删除（派生知识同步清除）+ 数据不出域（本期私有化）；**不做自动识别**（学习范围既定，建检测能力属过度设计） |
| 14 | **文档学习提取出错误逻辑，误导诊断** | 中 | 学习结果标注来源；关键结论仍需用户确认；置信度分级；可逐条修正 |
